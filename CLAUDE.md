# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A ground control station for simulated uncrewed vehicles (.NET 10 / ASP.NET Core backend,
React + Vite frontend, Postgres). It is early: the README's "What's real at this tag" table is
authoritative and is kept honest deliberately — do not add a claim to it that the code
does not honour.

## Commands

```bash
dotnet build                              # solution-wide; warnings are errors
dotnet test                               # all five test projects; needs Docker (see below)
dotnet run --project src/Mcs.Api          # http://localhost:5271

# a single project / class / method
dotnet test tests/Mcs.Core.Tests
dotnet test tests/Mcs.Core.Tests --filter "FullyQualifiedName~InMemoryTelemetryStoreTests"
dotnet test tests/Mcs.Core.Tests --filter "FullyQualifiedName~InMemoryTelemetryStoreTests.Write_ThrowsWhenAFurtherVehicleWouldExceedTheCap"
```

`tests/Mcs.Core.Tests`, `tests/Mcs.Api.Tests` and `tests/Mcs.Adapters.Tests` are pure unit tests
and need nothing — in particular the MAVLink suite needs no Python, because its byte vectors are
committed. `tests/Mcs.Integration.Tests` starts a real Postgres via Testcontainers, so **Docker
must be running** or that project fails.

`tests/Mcs.System.Tests` drives the running compose stack over HTTP and **skips itself when no
stack is listening**, so it stays out of the way of the inner loop:

```bash
docker compose --env-file .env -f deploy/compose/compose.yaml up -d --wait
MCS_SMOKE_REQUIRED=1 dotnet test tests/Mcs.System.Tests
```

`MCS_SMOKE_REQUIRED=1` turns "no stack" from a skip into a failure, and CI must set it — a smoke
suite that silently skips reports green for a run that asserted nothing. Origins come from
`MCS_SMOKE_BASE_URL` / `MCS_SMOKE_API_URL`, defaulting to the `.env.example` ports (8080 / 8081).
The project deliberately has **no project references**: it retypes the wire contract so a renamed
JSON property fails it rather than being refactored along with the API.

Running the API needs a Postgres — **without one it retries for 30s, logs, and exits
non-zero by design.** For the local inner loop:

```bash
docker run --rm -d --name mcs-pg -e POSTGRES_PASSWORD=dev -e POSTGRES_DB=mcs \
  -p 5432:5432 postgres:18-alpine
```

That matches the connection string hardcoded in `appsettings.Development.json`. Deployment
gets its connection string from `ConnectionStrings__Mcs`; there is no localhost default in
`Program.cs`, on purpose.

Frontend (`web/`): `npm run dev | build | lint`. It currently renders the offline basemap and
nothing else. `npm run build` runs `tsc -b` first, so type errors fail there rather than at lint.

`.env` is git-ignored and generated by `tools/bootstrap-env.sh` / `tools/bootstrap-env.ps1`
— never copy `.env.example` into place, its password is a deliberate placeholder.

`.github/workflows/ci.yml` is the authority on what has to pass: a `build-and-test` job (Release
build, then Core, Api, Adapters and Integration tests, then the web build and lint) and a `smoke` job that
runs `tools/bootstrap-env.sh`, brings the stack up and runs `Mcs.System.Tests` with
`MCS_SMOKE_REQUIRED=1`. Every compose invocation there carries `--env-file .env`, without which
the `:?` guards fail the command. The log dump on failure is ordered before teardown on purpose —
`down` takes the containers' logs with it.

Pinned versions that must agree across the repo: .NET SDK 10.0.302 (`global.json`, the SDK tag in
`src/Mcs.Api/Dockerfile`, and CI via `global-json-file`), Node 24.18.1 (`.nvmrc`, `web/Dockerfile`,
and CI via `node-version-file`), `postgres:18-alpine` (`PostgresFixture.PostgresImage` and
Compose). CI reads the version files rather than restating any of them.

## Architecture

```
src/Mcs.Core        domain: telemetry model, ingest boundary, bounded store
src/Mcs.Api         ASP.NET Core host; fake feed, persistence, observability live here
src/Mcs.Adapters    vehicle adapters; the hand-written MAVLink v2 framing codec lives in Mavlink/
src/Mcs.Simulator   stub until the air simulator lands
web/                React + TypeScript + Vite + MapLibre console
web/public/basemap  the offline MapLibre style; its rationale lives in the file's `metadata`
deploy/migrations/  numbered .sql, embedded into Mcs.Api and applied on startup
tools/mavlink-vectors/  the pymavlink generator for the codec's byte vectors
tests/              unit (Core, Api, Adapters) · integration (real Postgres) · system (compose smoke)
```

**`Mcs.Core` has zero package references and must keep them.** No logger, no web, no
database. `Mcs.Core.csproj` being empty is the enforcement.

### The load-bearing type distinction

`VehicleTelemetry` is only what a vehicle *claimed*. `TelemetryFrame` pairs it with
`ReceivedAtUtc`, the station's own observation. `TelemetryFrame`'s constructor is internal
and `TelemetryReceipt.Complete` is its only caller, so no adapter can mint a frame or stamp
one with a vehicle's clock. Ingest is deliberately two-phase — `ingest.BeginReceive()` →
decode → `receipt.Complete(telemetry)` — so the clock is read at arrival and decode cost is
*measured* (`IngestDelay`) rather than baked invisibly into the data's recorded age. A
receipt completes exactly once.

### The store's concurrency contract

`InMemoryTelemetryStore.Write` holds `_subscriberGate` across resolve-or-admit + append +
fan-out, as one critical section; readers never take that gate. Splitting the write across
the gate produces duplicate delivery or silent loss — `docs/notes/stuck.md` (2026-08-08)
works through all three placements. Bounds are system-wide commitments on `ITelemetryStore`:
12 vehicles, 600 frames each, 256-frame drop-oldest subscriber queues.

### The MAVLink codec and its byte vectors

`src/Mcs.Adapters/Mavlink` is a hand-written v2 framing codec: a streaming parser, a serialiser,
CRC-16/MCRF4XX, and the message-definition table. It is framing only — the payload is bytes, and
nothing there knows what message id 33 means. Framing fails loudly and semantics fail quietly, and
merging them puts the quiet failures where the loud ones are.

**The codec is proved against pymavlink, not against itself.** A parser fed its own writer's output
agrees with itself no matter how wrong both halves are — a transposed CRC seed, a checksum over the
wrong span and an off-by-one truncation rule all cancel exactly. So `tests/Mcs.Adapters.Tests`
asserts decode *and* encode separately against committed vectors, and encode must reproduce
pymavlink's bytes **byte for byte**. Round-trip tests exist but are explicitly not the evidence.

Those vectors are generated by `tools/mavlink-vectors/generate.py` and committed alongside it. **CI
must never need pymavlink** — a second language toolchain is a cost every contributor pays forever —
but a fixture with no generator is a magic number the size of a file, so both ship. The generator is
deterministic and the check on it is that rerunning it leaves `git diff` empty; that is also why the
fixture carries a `.gitattributes` `eol=lf` entry. pymavlink is pinned to 2.4.42, which is not the
newest release, for the reason recorded in `requirements.txt` and `docs/notes/stuck.md`.

Two decisions worth not relitigating. The `CRC_EXTRA` seeds cover **only** the message ids the
station decodes — the alternative, generating the whole dialect's table, buys the ability to
checksum messages that are then discarded. And **resync discards exactly one byte**, not the
buffer: a corrupt frame is very often followed immediately by a good one, and losing a frame the
station already received in full is HAZ-01 by another road.

**Nothing is discarded on the word of a length byte that cannot be verified.** That short seed table
means an unknown message id has no checksum available, so its length claim is corroborated instead:
the byte just past the claimed frame must be a start byte, since MAVLink frames run back to back. It
matters more than it sounds — unknown traffic is the *common* case on a real link, and before the
guard existed ten bytes of noise ahead of eight valid position reports delivered one and destroyed
seven, recorded as a single `UnknownMessagesSkipped`, a counter documented as ordinary traffic. A
real loss reported by the one number meaning everything is fine. v1 frames and signed frames get the
same treatment for the same reason: verify first, then step over.

One exposure remains and is deliberate. A false start byte declaring a large payload delays every
frame behind it until those bytes arrive, because it cannot be told from a genuine frame split
across two reads — and genuine splits are ordinary, so resyncing past it would destroy real frames.
Nothing is lost, only delayed, and `IncompleteCandidate_DelaysTheFramesBehindItButDoesNotLoseThem`
pins that. Removing the delay needs the parser to look past an unresolved candidate and deliver
verified frames from behind it; that is a larger change than framing needs and would deliver out of
order.

A payload **longer** than the definition is kept, not rejected. v2 extension fields are excluded
from `CRC_EXTRA` by design, so a newer sender's frame validates against an older receiver's seed and
arrives longer than declared; the format's instruction is to read the fields you know and ignore the
rest. Rejecting it would break exactly one message type against current firmware — `SYS_STATUS` has
grown extension fields — and leave every other one working, which is the quiet per-message failure
this codec is arranged to prevent.

Nothing in the parser logs. Every discard increments a counter on `MavlinkParserStatistics`, because
a ground station sees dozens of message types it has no decoder for and a log line each would train
whoever is watching to ignore the stream. Signing is not implemented and will not be — signed frames
are rejected and counted, and the README's limitations section says so.

### Startup and persistence

`DatabaseStartup` is an `IHostedLifecycleService` using `StartingAsync` specifically so it
runs before Kestrel listens. It retries a Postgres that is still coming up (transient errors
only — a bad password or a drifted checksum fails immediately) and stops the host if the
budget expires. `SchemaMigrator` takes a Postgres advisory lock, applies each unrecorded
migration in its own transaction, and records a SHA-256 of it in `schema_version`.

**A migration is immutable once shipped.** A checksum mismatch throws `SchemaDriftException`
and the station will not start; the fix is always a new numbered file. Versions must be
contiguous from 1. Migrations are embedded resources (`Mcs.Api.csproj` globs
`deploy/migrations/*.sql`) — adding a file is the whole step, but note checksums normalise
`\r` because `.gitattributes` lets these files check out CRLF on Windows.

`/health` (liveness) runs no checks at all and must stay that way; `/health/db` (readiness)
is the one allowed to go red, and reports applied vs. compiled-against schema version.

### The offline basemap

**Nothing the console loads may come from another origin.** `docker compose up` is required to
run everything offline with no accounts, so a tile CDN or an API key would make the README's
claim false at the first tag. `web/index.html` carries a `default-src 'self'` CSP that turns
that from a thing you once checked in DevTools into a thing that fails loudly; `'unsafe-inline'`
is load-bearing there for MapLibre's inline style attributes and the dev server's HMR preamble.

The style is `web/public/basemap/style.json`, and **it must never grow a `sprite` or `glyphs`
key** — MapLibre fetches glyph files the moment a layer uses a text field, which is why the
basemap has no labels at all. It ships no geodata: `graticule.ts` generates the grid from the
viewport, choosing spacing from a 1-2-5 ladder so the division count stays in single digits at
every zoom. Rationale for all of it is in the style file's `metadata` block, which MapLibre
ignores and JSON has no comments for.

MapLibre v6 derives its worker URL from `import.meta.url` at runtime, which no bundler can see,
so `basemap/worker.ts` sets it explicitly from a `?worker&url` import. Without that the basemap
paints and every data layer stays silently empty.

### Logging

Serilog, two-stage init in `Program.cs`, compact JSON to stdout, configured from the
`Serilog` section so `Serilog__MinimumLevel__Default` works on a running container.
`Enrich.FromLogContext` stays in code because `CorrelationIdMiddleware` depends on it.
Health-probe and SSE request lines are logged at Debug on purpose.

## Conventions

- **`TreatWarningsAsErrors` plus `NuGetAudit` at `all`/`low`** (`Directory.Build.props`).
  A transitive advisory fails your local build, not CI. Pin forward explicitly rather than
  taking latest — see the NU1903 entry in `docs/notes/stuck.md`.
- **Comments carry the rejected alternative, not a restatement of the code.** XML doc
  comments on types explain why the shape is what it is; `//  ` (two spaces) implementation
  comments explain a non-obvious line. This density is intentional — match it. When prose
  above a type becomes false after a change, rewriting it is part of the change.
- **Reject, never clamp.** A clamped 200% battery renders as a believable 100% and hides a
  broken adapter. Same reasoning for a rejected thirteenth vehicle and for dropping the
  *oldest* frames in a full subscriber queue. The hazard the whole system is designed
  against (referred to as HAZ-01) is a console confidently showing a picture that is not
  current.
- **Time comes from an injected `TimeProvider`.** No `DateTimeOffset.UtcNow` anywhere;
  durations use `GetTimestamp`/`GetElapsedTime`, not wall-clock subtraction.
- Identifiers like `MCS-001`, `HAZ-01`, `C1`, `§2.3` in comments refer to the project plan
  and requirements, which live in the git-ignored `internal/` directory (plan, milestone
  tickets, walkthroughs). Read them there for context on what a ticket number means.
  **`internal/` is never committed, on any branch.**
- Log anything that costs more than ~30 minutes to `docs/notes/stuck.md`: date, symptom,
  what you tried, what it was. Contemporaneous, not polished.
- Commit per ticket, minimum.
